BITS WILP

Design and Evaluation of a Secure GitOps CI/CD Pipeline
with Automated Rollback using ArgoCD and Prometheus

Mid-term dissertation presentation

Project Objective

To build a GitOps workflow that keeps deployment state controlled through Git and reconciled automatically in Kubernetes.

Core Idea

Git is the source of truth, Kubernetes runs the app, and ArgoCD ensures the cluster matches the repository state.

Slide 1

1. Problem Statement

Traditional CI/CD

  • Deployments happen directly to infrastructure
  • Configuration drift is common
  • Recovery is slow and manual
  • Rollback and audits are harder

GitOps Advantage

  • Git becomes the source of truth
  • Deployments are declarative and versioned
  • Drift is detected automatically
  • Recovery is faster and more reliable

Key message: GitOps improves reliability, traceability, and recovery in modern cloud-native systems.

Slide 2

2. Motivation

In production environments, application delivery must be fast but also safe and recoverable. Modern teams need a deployment model that supports automation, versioning, and clear operational control. GitOps provides this by treating Git as the system of record.

Required Benefits

  • Faster deployment cycles
  • Lower operational risk
  • Better traceability
  • Stronger incident recovery

Technical Advantage

  • Declarative infrastructure
  • Continuous reconciliation
  • Improved consistency
  • Observability and health checks
Slide 3

3. Proposed Architecture

GitHub stores source code and Kubernetes manifests.

GitHub Actions builds and validates the Docker image.

ArgoCD syncs the live cluster state with Git.

Kubernetes runs the application and maintains deployment state.

Prometheus and Grafana monitor and visualize system health.

This model separates the desired state from the live state and continuously reconciles them.

Slide 4

4. Deployment Flow

  1. Developer pushes updates to GitHub.
  2. GitHub Actions builds the container image.
  3. Docker packages the application.
  4. Kubernetes manifests define the desired state.
  5. ArgoCD compares actual and desired state.
  6. ArgoCD reconciles the cluster to match Git.

Important: The deployment is controlled through Git, not by direct manual changes to the live environment.

Slide 5

5. Demo Flow

  1. Show cluster status: kubectl get pods -A
  2. Show deployment and service: kubectl get deployment and kubectl get svc
  3. Open the app using the Kubernetes service
  4. Check health endpoint: curl http://localhost:8080/health
  5. Explain ArgoCD reconciliation
  6. Conclude the pipeline is functioning end-to-end

Expected outcome: the service is live, healthy, and consistent with the Git-based desired state.

Slide 6

6. Monitoring and Reliability

Prometheus

  • Collects metrics from workloads

  • Supports alerting logic

Grafana

  • Presents operational trends

Health endpoints and monitoring improve reliability by making failures easier to detect and respond to.
